## 一、设计目标

| 目标 | 说明 |
|------|------|
| 安全 | 所有变更操作必须经过人工确认，高风险操作需二次确认，杜绝 AI 擅自执行 |
| 高效 | 熟练用户可在 0.5 秒内完成确认，不打断工作流 |
| 可理解 | 新手用户能通过 AI 解读理解变更含义，做出知情决策 |
| 可追溯 | 每一次确认/拒绝都被记录，支持事后审计和合规审查 |
| 可配置 | 用户可根据自身场景调整确认卡的触发频率和展示深度 |

## 二、用户场景与角色

| 角色 | 使用场景 | 对确认卡的核心诉求 |
|------|----------|-------------------|
| 熟练运维 | 日常巡检、批量操作、紧急故障处理 | 快速通过，不被频繁打断 |
| 兼职运维/开发负责人 | 临时处理服务器问题、审批变更 | 能快速理解变更含义，敢于点「允许」 |
| 技术管理者 | 审批重大变更、查看审计报告 | 能看到完整的变更上下文和审批记录 |
| 新手运维 | 学习阶段、跟着 AI 操作 | 能通过解读理解每个操作的含义 |

## 三、信息层级设计

确认卡的信息分为三个层级，用户可以根据自己的需要选择查看深度。

### 第一层：一眼决策区

展示用户在 0.5 秒内做出决策所需的全部信息。

包含字段：

- 操作类型图标（修改文件/重启服务/删除文件/执行脚本等）
- 目标主机名
- 风险等级（颜色标识 + 文字）
- 文件路径或操作对象
- 关键变更摘要（一行，diff 格式）
- 两个主要操作按钮

### 第二层：详情区

用户点击「展开详情」后展示：

- 完整命令原文（可复制）
- 变更内容 diff（绿色/红色高亮）
- 影响范围说明（由本地规则/AI 根据命令推断）
- 执行用户和时间（有则展示）
- 「🤖解读变更」入口在确认卡**底栏左侧**（不在详情区内）

### 第三层：AI 解读区（弹窗）

默认不展示、不请求。用户点击底栏「🤖解读变更」后才实时生成，并以**弹窗**展示（按钮文案前小转圈；弹窗底：取消 / 我已知晓）。

设计要点：

- 顶部明确标注「仅供参考，请以实际为准」
- 底部免责声明：最终是否执行，请以专业判断为准
- 解读内容包含：一句话概括、影响分析、风险提示
- 解读内容不包含倾向性建议（如「建议执行」），只陈述事实

## 四、交互流程

### 4.1 单次确认（标准流程）

用户意图 → AI 生成命令 → 弹出确认卡（第一层）→

- 「允许本次」→ 执行 → 审计
- 「拒绝」→ 不执行 → 审计
- 「展开详情」→ 完整命令 / diff → 点击「AI 解读此变更」（实时生成，按钮前小转圈）
- 超时无操作 → 自动拒绝 → 审计

### 4.2 批量确认（多个主机或多个文件）

**本期不做。** 见 PRD 原方案：全部允许 / 全部拒绝 / 逐条查看。

### 4.3 高风险操作二次确认

高危卡：红色边框；点「允许」后需再输入 `YES` 确认（通用口令，不限删除场景）。

高风险操作的定义（实现以 `confirm_card_meta` + 现有高危启发式为准）：

- 删除文件或目录
- 停止关键服务
- 修改防火墙规则
- 格式化磁盘或分区
- 修改系统关键配置
- 执行数据库 DROP / DELETE 等

## 五、视觉与交互规范

### 5.1 风险等级颜色

| 等级 | 说明 |
|------|------|
| 低风险 | 细边框；创建临时文件、修改非关键配置 |
| 中风险 | 中等边框；修改服务配置、重启非关键服务 |
| 高风险 | 粗边框（可轻微脉动）；删除、停服务、改防火墙等 |

### 5.2 按钮

- 拒绝：次要，左侧
- 允许本次：主色，右侧（颜色可随风险等级）
- 🤖解读变更：确认卡底栏左侧；点击后弹窗展示解读（取消 / 我已知晓）

### 5.3 动效

本期仅极简 CSS（高危边框脉动可选）；完整动效属后续。

## 六、AI 解读功能详细设计

### 6.1 功能定位

AI 解读是辅助决策工具，不是决策替代品。

### 6.2 触发方式

| 方式 | 说明 |
|------|------|
| 用户手动点击「AI 解读此变更」 | **唯一默认**：点击后实时请求 `POST /api/mobile/demo/permission/explain` |
| 挂卡预生成 / 高危默认展开 | **不做**（避免未需要时也解读） |
| 新用户引导期自动展示 | **本期不做** |

加载态：底栏「🤖解读变更」按钮文字前显示小转圈，同时弹窗显示「正在解读…」；完成后移除转圈，弹窗展示解读正文（底部：取消 / 我已知晓）。

### 6.3 解读内容结构

| 段落 | 内容 |
|------|------|
| 一句话概括 | 变更做了什么 |
| 影响分析 | 对性能/资源/稳定性的影响 |
| 风险提示 | 可能带来的风险（必填） |
| 免责声明 | 固定文案 |

生成策略：**优先 LLM 实时生成**；不可用时回落**本地模板**（`confirm_card_meta.build_ai_explanation`）。

### 6.4 免责声明

> 此解读由 AI 生成，仅作参考。最终是否执行，请以你的专业判断为准。如有疑问，建议查阅官方文档或在测试环境验证。

### 6.5 质量要求

- 必须包含「风险提示」
- 不确定时说明「此命令不常见，请谨慎确认」
- 不得含「强烈建议执行」等倾向性措辞

## 七、状态管理与超时处理

| 状态 | 说明 |
|------|------|
| 等待确认 | 展示中；超时后自动拒绝（ACL 默认 120s） |
| 已允许 / 已拒绝 / 已超时 | 记录审计 |

「记住我的选择」：**本期不做**（高危不允许记住）。

## 八、移动端适配

按钮置底、详情/解读用底部 sheet：**本期在 Demo Web 落地折叠与 sheet 形态**；推送通知确认后续做。

## 九、审计记录

每次允许/拒绝/超时记录（字段对齐实现）：

- timestamp、card_id / permission_id、conversation_id、user、host
- operation_type、risk_level、command、decision
- ai_explanation_viewed（可选）
- execution_result（执行后）

## 十一、一句话总结

确认卡是掌上运维 AI 助手的安全基石。三级信息层满足不同用户：熟练用户快速确认，犹豫用户通过解读理解变更，高风险强制二次确认。AI 解读是辅助决策工具，不是决策替代品——每一次操作都被完整记录。
