一、项目背景与目标

现有的 ai-ops-assistant 已具备自然语言 → 任务链 → SSH 执行链路，但交互方式是「表单提交 → 后台执行 → 结果展示」的离线批处理模式。用户无法实时感知执行过程，也无法在执行过程中干预或确认。

工业级稳定性

会话管理、断线重连、权限管控、审计日志等企业级能力

4.3 LLM Prompt 设计

## 系统角色
你是一个 Linux/Unix 运维命令翻译专家。用户用自然语言描述操作，你将其翻译为精确的
shell 命令。当前平台：Web 终端 + 多主机管理。

## 当前环境信息
- 主机名: {hostname}
- 操作系统: {os_type}（如 CentOS 7, Ubuntu 22.04）
- 默认 shell: {shell_type}
- 当前目录: {pwd}

## 翻译规则
1. 只返回命令本身（一行），不加任何前缀或解释
2. 多条命令用 `&&` 连接（最多 3 条，超出建议用户分步执行）
3. 如果命令需要 sudo，添加 `sudo` 前缀
4. 问询/分析类请求（"分析"、"告诉我"、"为什么"）→ 返回 `__EXPLAIN__:{分析内容}`
5. 危险命令（rm -rf /、格式化磁盘、dd over /dev）→ 返回 `__REFUSE__:拒绝执行`

## 输出格式（严格 JSON）
{
  "command": "df -h",
  "description": "查看所有分区的磁盘使用情况（人类可读格式）",
  "risk_level": "low|medium|high|critical",
  "risk_note": "低风险 — 只读操作，不修改任何数据",
  "estimated_time": "1-2秒",
  "requires_sudo": false
}

## 示例
用户: 帮我查看磁盘使用情况
{
  "command": "df -h",

9.1 paramiko PTY 异步读取

async def _read_loop(self, session_id: str):
    import asyncio
    session = self.sessions.get(session_id)
    if not session:
        return
    channel = session.shell
    ws = session.websocket
   
    while True:
        if not session.active:
            break
        try:
            await asyncio.sleep(0.02)  # 20ms 轮询
            if channel.recv_ready():
                data = channel.recv(4096).decode('utf-8', errors='replace')
                asyncio.create_task(ws.send_json({
                    "type": "output", "data": data
                }))
            if channel.exit_status_ready():
                break
        except Exception:
            break
