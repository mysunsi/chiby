## 0. 对外口径定稿（先读这里）

| 层级 | 怎么说 | 怎么说容易被拆穿 |
|------|--------|------------------|
| **主标题** | 企业级 **AI 可信执行环境** / **驾驭层（Harness）** | 「赤壁 = 完整 AI 操作系统已交付」 |
| **副标 / 对标** | 能力分层对标政策语境中的 **AI OS 方向**（约束·上下文·审计·插件） | 「我们就是北京新政意义上的 AI OS」「唯一 AI OS」 |

## 1. 定义（品类语言，非已完成称号）

> **AI 安全操作系统（AI Security OS）**——在本文中作为**能力品类/对标语言**：指横跨 AI 任务生命周期的治理与执行基础设施。  
> 赤壁在该品类下交付的是 **驾驭层**：把大模型推理放在企业规则、权限、流程与审计边界内运行，使 AI 行为尽可能成为「经授权、可追溯、可问责」的企业操作。

| 是 | 不是 |
|----|------|
| **更可信的 AI 执行环境**（驾驭层 / Harness） | 「更大/更聪明」的基座模型 |
| Agent 宿主 + 护栏 + 上下文 + 插件 | 单独一个聊天机器人 |
| 可对标政策语境中的企业级 AI OS **方向** | 已建成 Windows/安卓级完整 OS 或全市唯一底座 |

**一句话**：赤壁卖的不是「AI 能聊天」，而是「AI 在企业里凭什么被允许动手」。

## 2. 四层机制 ↔ 赤壁模块（诚实映射）

### 2.1 执行约束层（Process Control）

**OS 类比**：内核调度 / 系统调用拦截  
**职能**：在执行落地前拦截、校验、裁决——降低越权与偏流程风险。

| 子机制 | 赤壁模块 | 状态 | 说明 |
|--------|----------|------|------|
| 意图路由 | Intent Router | **设计中** | 小思关键字/事务 vs AI；未合入掌上主路径 |
| 表单/事务校验 | 小思 `ProcessMessage` + 表单引擎 | **已交付（小思侧）** | 尚未以 `xs_*` 稳定接到赤壁编排 |
| 执行裁决 | 确认卡 v2 | **已交付** | 变更确认；高危 YES；可选 OTP |
| 选机硬边界 | Host ACL + 选机违规拦截 | **已交付** | 越权主机可硬拦 |
| 权限前置 | `user_capabilities` → CDU | **设计中** | 调用前告知能力边界 |
| 操作边界 | 策略令牌等 | **规划/申请中** | 勿标为已商用功能 |

**对外可演示（本层）**：确认卡 + 主机 ACL/选机约束 +（演示环境）三模式执行闸门。  
**勿写「已可演示」**：意图路由、小思表单已接进赤壁主对话（除非现场真接上）。

---

### 2.2 信任记录层（Trust Ledger）

**OS 类比**：系统日志 / Journal  
**职能**：捕获关键行为，支撑审计、问责与事后验证。

| 子机制 | 赤壁模块 | 状态 | 说明 |
|--------|----------|------|------|
| 操作审计 | 审计 JSONL + Turn Trace | **已交付** | 意图/工具/确认/执行等 |
| 脱敏 | redaction | **已交付** | 审计与回灌去凭据 |
| 链式哈希证据链 | 专利方案 | **申请中** | 有审计底座 ≠ 已上线链式哈希 |
| 短时凭据绑定 | ExecTicket 等 | **部分交付** | TSM-A 有开关；完整密码学叙事勿过满 |
| 影子回放验证 | Shadow Mode | **设计中** | 文档 ≠ 产品演示 |
| 合规报告包 | 等保/GDPR 模板 | **规划中** | |

**对外可演示**：审计大屏 / JSONL / Turn Trace。  
**勿写「已可演示」**：影子模式、不可篡改链式账本（除非另有实现证明）。

---

### 2.3 知识与上下文层（CDU + Knowledge）

**OS 类比**：进程上下文 / 环境变量  
**职能**：权威上下文注入；知识检索补充，而非放任模型「凭空记得」。

| 子机制 | 赤壁模块 | 状态 | 说明 |
|--------|----------|------|------|
| 上下文注入 | CDU + HostTargets | **已交付** | hydrate / resolve / inject |
| 权限上下文 | operate → `user_capabilities` | **设计中** | |
| 业务对象上下文 | 动态对象工具生成器 | **设计中** | P2；先薄 `xs_*` |
| 知识检索 | KnowledgeHub + DocHub + `kb_*`/`doc_*` | **已交付** | 双轨可查可管 |
| 「命中则免 LLM」 | 知识优先调度 | **设计中/部分** | 有工具与文档意图快路径；**勿写固定命中率** |
| 时间维 RAG | 时间戳 metadata | **设计中** | |

**对外可演示**：选机 CDU 持久化 + 知识/文档双轨 + Agent 工具检索。  
**建议表述**：知识优先是**方向与部分路径**，不是已证明的固定免推理比例。

---

### 2.4 生态扩展层（Plugin & Hooks）

**OS 类比**：驱动 / 系统调用表  
**职能**：标准契约扩展业务能力，而不是把逻辑写死进模型。

| 子机制 | 赤壁模块 | 状态 | 说明 |
|--------|----------|------|------|
| 工具契约 | `tools/plugins/` + manifest | **已交付** | 权限/确认策略可声明 |
| 工具市场预览 | `/demo/tools-marketplace` | **已交付（浏览）** | 非完整商业商店 |
| 应用隔离 | `application/` + 白名单装载 | **设计中** | |
| 小思适配 | `xs_*` + ProcessMessage | **设计中** | |
| 生命周期 Hooks | HookRegistry | **规划中** | |

**对外可演示**：插件化工具加载与市场预览页。

## 3. 叙事对比（对外幻灯可用）

| 维度 | 传统 Agent 话术 | AI 安全 OS（赤壁）话术 |
|------|-----------------|------------------------|
| 核心问题 | AI 能做什么？ | AI 在企业里凭什么被信任？ |
| 执行 | 模型规划 → 执行 | 路由/规则 → **确认/拦截** → 执行 → **审计** |
| 数据 | 参数记忆 + 随意 RAG | **CDU 权威上下文** + 权限过滤检索 |
| 边界 | Prompt（软） | 确认卡 + ACL +（规划）策略令牌（硬） |
| 追溯 | 聊天记录 | Turn Trace / 审计（链式哈希为增强） |
| 扩展 | 多塞工具 | **标准插件契约**接入业务 |
| 交付物 | 能聊天的 AI | **可治理的 AI 执行环境** |

## 4. 对内对齐：能力水位一览

```text
已能演示的「安全 OS 内核」：
  确认卡 + 主机 ACL/选机 + 审计/Turn Trace + CDU(HostTargets)
  + 知识双轨 + tools/plugins

正在长出来的「业务 OS」：
  意图路由 + 小思 xs_* + user_capabilities + 应用目录

增强与护城河叙事（勿当现货）：
  链式审计哈希、策略令牌专利、影子模式、动态对象生成器、合规报告包
```

---

## 5. 使用纪律（避免叙事反噬）

1. **OS = 驾驭层叙事**，承认规划脑可为 Hermes/第三方模型。  
2. **小思能力写清归属**：表单引擎「已交付」在小思；赤壁侧在适配器上线前写「设计中」。  
3. **「可演示」只列第 2 节各层「对外可演示」**，设计文档不算演示。  
4. 对接新政：对标 Harness / 可信执行 / 分级治理，不抢「唯一 AI OS」。  
5. 定价权来自**可演示护栏 + 可接入业务**，不是来自四层名词本身。
